返回类型 由你设计函数时决定，取决于你要返回什么类型的值。

形参与实参

函数声明与调用

C++ 编译器从上往下编译，函数在被调用之前必须先声明或定义。 因此，被调用的函数通常写在调用它的函数前面。

函数传参

函数传参：按值、按引用、按指针

一、如何从代码形态上区分

二、三种传递方式的本质区别

1. 按值传递

传过去一个副本

函数内怎么修改，都不影响原对象

代价：需要新建副本，占用额外时间和空间

2. 按引用传递

传过去的是原对象的别名（底层通过地址实现）

函数内直接操作原对象

代价：不新建副本，但可能意外修改原对象

3. 按指针传递

传过去的是原对象的地址

函数内需要先解引用（*biao），才能操作原对象

效果和引用一样：操作的是原对象

后两者都是操作原对象，只不过方式不同：引用直接操作，指针需要先解引用。

三、按值传递 vs 按引用传递：什么时候用引用

当参数很大时（如一个大容器），按值传递会新建一个副本，浪费时间和空间。 此时应该用引用传递（不建副本），但如果又怕函数内意外修改原对象，就用：

cpp

const vector& biao // 常量引用传递

只读，不建副本，安全高效。

四、引用传递 vs 指针传递：从返回类型的角度看区别

链式调用示例

返回指针：*(func()).method() 或 func()->method()（麻烦）

返回引用：func().method().method2()（流畅）

引用返回更适合链式调用，因为它返回的是对象本身，不是地址。

现阶段理解这些还为时过早，初学者只需掌握函数传参时传引用和传指针的区别即可，返回类型的不同可以先不做深究

**。但等你学到运算符重载的时候，涉及到返回引用这种不常见的返回类型时，要想起来这里讲过。 不要问“为什么不返回指针”——因为虽然返回指针在原理上和返回引用类似，也能实现运算符重载，但返回指针会破坏链式调用的自然写法（比如 a.add(b).add(c) 用引用可以直接点，用指针就得写成 a.add(b)->add(c) 或 (a.add(b)).add(c)，不自然）。 所以运算符重载里通常返回引用，而不是指针。*

常量引用传递

为什么需要常量引用？

当一个参数很大时（比如一个巨大的 vector）：

按值传递：会新建一个副本，浪费时间和空间

按引用传递：不建副本，但函数体内可能意外修改原对象

我们想要的是：不建副本 + 只读，不能修改原对象。

这就是 常量引用传递 的作用。

写法

cpp

void func(const vector& biao) // 形参列表里加 const

函数重载

重载是指在同一个作用域内，允许多个函数或运算符拥有相同的名称，但参数列表不同（参数的类型、个数或顺序不同）的一种机制。编译器根据调用时提供的参数来决定调用哪个版本，这样就能实现同一函数名但不同函数的区分。

值得注意的是

函数重载不能由返回类型区分

也就是函数名前的类型无法区分同名函数

因为函数调用时 编译器不考虑返回类型 故函数名前的类型不同不能实现函数重载

using namespace std;

cout << 114 << endl;

}

void hanshu(string str) {//如果去掉string str 导致两个函数同名 会导致运行时错误

cout << 514 << endl;

}

cout << 1919810 << endl;

}*/

int main() {

指针

指针内容为地址,地址指向内容 实现内容绑定

指针是这样一个结构

1指针本身有自己的地址 &q

2指针储存内容是指向的地址 int*q=&a

3解指针的解是顺着指针储存的地址把目标找出来一个过程 解开并不代表指针储存目标值 只是 * 顺着指针提供的路线跑过去打开了 *q

#include<bits/stdc++.h>

using namespace std;

int main() {

int a=100;//声明了a=100

int* q;//类型 星号 变量名 是指针的声明格式 注意和 星号 变量名解指针区分开

q=&a;// &是取地址运算符 &a就把a的地址拿过来了 让指针q等于了一串地址

cout<<q<<endl;//输出q包含的指针

cout<<&q<<endl;//输出q自己的地址 不是输出包含的地址

cout << (q);//这个q 不是声明指针q的意思 而是解指针地址对应的内容

}

输出结果 一行随机变的数 另一行随机变的数 一行100

数组的名称 会隐式转化为对数组取指针

char table[256];

scanf(“%s”, table);//不用写取地址符& table名称就是取table这个数组的指针了

scanf(“%c”, &table[0]);//取数组的第一个字符的地址 &

函数按引用传参和指针传参的关系

函数按指针传参实现修改a的值

#include<bits/stdc++.h>

using namespace std;

void work(int* q) {//现在就是int*q=&a了

cout << q << endl;//输出的是&a 即随机的地址

cout << (*q)<<endl;//输出100

*q = 200;//指针q需要解引用(*q) 操作获取到地址对应具体内容后 才能 = 200 修改值

}

int main() {

int a = 100;//声明了a=100

work(&a);//对work 取a的地址传过去作为参数

cout << a;//a的值在work里被修改了

}输出结果 一行随机变的数 一行100 一行200

函数按引用传参实现修改a的值

#include<bits/stdc++.h>

using namespace std;

void work(int &q) {//相当于 按指针传过来的q直接是解引用完毕的int类型值 和a共享一个地址

cout << q << endl;//输出的是a的值

q = 200;//共享一个地址 q修改a也会修改 形参列表int改成int & 就实现了按值传递变为按引用传递

}

int main() {

int a = 100;//声明了a=100

work(a);

cout << a;//a的值在work里被修改了

}

实际上 按引用传参 是基于按指针传参封装的

栈指针与堆指针

如上 上面指针一栏涉及的都是栈指针

栈指针的生命周期 仅在当前作用域存在

只有指针才有深拷贝浅拷贝的概念 详见5类与实例

#include<bits/stdc++.h>

using namespace std;

int* badFunc() {

int a = 100; // a出生（栈上）

int* p = &a; // p出生（栈上），指向a

cout << “函数内 *p指向: “ << *p << endl; // 100

return p; // 返回p存的地址

} // a和p都死亡！返回的地址失效

int main() {

int x = 10;

int* p1 = &x; // p1出生，指向x

cout << “p1指向: “ << *p1 << endl; // 可以正常顺着p1储存的地址找到x的值10并输出

if(1)

{

int y = 20;

p1 = &y; // p1改指向y

cout << “作用域内 p1指向: “ << *p1 << endl; // 20

} // y死亡！p1变成野指针

cout << “p1指向旧地址: “<< p1<<endl; // 这时候p1 还没被销毁 依旧储存着y的路径 但是y已经死亡 它的储存随时会被覆盖 但是大概率p1等于原来的y值

p1 = &x; // 重新指向x

cout << “重新指向后: “ << *p1 << endl; // 10

int* p2 = badFunc(); // p2拿到失效的返回p的地址

cout << “p2指向旧地址: “ << p2; // 这时候p2 还没被销毁 依旧储存着a的路径 但是y已经死亡 它的储存随时会被覆盖 但是大概率p1等于原来的a值

return 0;

} // x和p1和p2死亡

堆指针实现长期保存内存值

new int(x) 是在堆上建立一个int 类型的对象其值为x 并返回x的地址

#include<bits/stdc++.h>

using namespace std;

// 修改1：badFunc 改成堆版本

int* goodFunc() {

int* p = new int(100); // 堆上建立一个新对象 int 100 并返回其地址给指针p

cout << “函数内 *p指向: “ << *p << endl;

return p; // 返回堆地址（安全）

} // p死亡，但堆上的100还在

int main() {

int x = 10;

int* p1 = new int(x); // 修改2：p1直接指向堆内存，拷贝x的值

cout << “p1指向: “ << *p1 << endl; // 10

// 修改3：在堆上创建y

int* y = new int(20);

delete p1;// 先释放原来的堆内存(10)

p1 = y; // p1指向=指针y

cout << “作用域内 p1指向: “ << *p1 << endl; // 20

// 注意：这里没有if作用域了，y是堆上的，不会自动销毁

cout << “p1指向堆地址: “ << *p1 << endl; // 20（永远安全）

// 修改4：重新指向堆上的x

delete p1; // 先释放原来的堆内存（20）

p1 = new int(x); // 重新分配堆内存，存10

cout << “重新指向后: “ << *p1 << endl; // 10

// 修改5：使用goodFunc

int* p2 = goodFunc(); // p2拿到堆地址

cout << “p2指向堆地址: “ << *p2 << endl; // 100（安全）

// 修改6：修改堆上的值

*p2 = 999;

cout << “修改后p2: “ << *p2 << endl; // 999

// 最后记得释放所有堆内存

delete p1;

delete p2;

return 0;

} // 所有堆内存都已释放，安全！

堆版本特点：所有指针指向堆内存，数据长期保存，手动释放才消失！

用堆指针保证内存安全不被覆盖 就比普通的指针多了一个创建时的new

以及想要更换指向需要释放内存再new

继承（派生）

在复制的原理上：拷贝和继承之间的区别

拷贝是对象层面的操作。指用一个已存在的对象，去创建另一个同类的新对象，并将成员变量的值复制过去。

继承是类层面的关系。指一个类（子类）复用另一个类（父类）的成员（属性和方法），并可以扩展或重写。其中子类又叫派生类 父类又叫基类

所谓的复用是指 继承是在编译时，把父类的所有成员定义直接”复制粘贴”到子类中！

这样就能减少相同代码的重复书写

子类继承父类内容的语法

子类时这样声明 class子类:继承类型 父类{子类的专属内容};

在访问的方式上:友元和继承之间的区别

友元函数友元类等并不是被访问类的内部成员,但是它被特别授权,可以**访问甚至修改被访问类的所有内容,彻底破坏了封装,**内部成员支持任意修改。

继承则不同。子类继承父类后所做的修改，并不会影响父类原本的内容，因为继承相当于在子类中新建了一份父类的成员副本，修改的是这份副本，而非父类本身。

继承时，子类无论如何都无法修改父类对象的内容！

JAVA里没有友元的概念

就相当于 指针变量b在子类里又建立了一遍 和父类的指针变量b没有啥关系

protected 保护访问权限 限制类内部和子类访问

继承成员和子类声明的成员同名处理

当子类继承父类的m_a时 m_a就能调用 但是在再子类里声明int m_a会怎么样呢？

那么原来默认表示子类继承成员的m_a,现在变成表示子类自身成员m_a了,当我们想要对子类继承来的m_a 做操作时 就需要再明确是父类的继承 用 父类名:: 来明确

#include<bits/stdc++.h>

using namespace std;

class Base {

public:

int m_a;

Base() {

m_a = 100;//父类的m_a成员值为100

}

};

class Son:public Base {

public:

int m_a;//又在子类里声明了继承的m_a

Son() {

m_a=300;//这时候 子类构造函数里的这个m_a就是默认调用子类新建的成员 不是表示继承来的m_a了 如果我这时候想修改继承来的m_a的值 这该怎么办呢

Base::m_a = 200;//继承的m_a 需要强调Base::下的作用域 就能明确是指继承的对象了

}

};

int main() {

Son son;

cout << son.m_a << endl;//输出的是对象son的新建的成员m_a

cout << son.Base::m_a;//输出的是对象son继承来的m_a

}

注意这个对父类继承来的m_a操作不是对原父类成员m_a做操作 继承来的m_a是父类成员的m_a的副本

别被父类成员m_a 子类继承成员m_a 和子类成员m_a 搞晕了

当然对于成员函数也是一样的

#include<bits/stdc++.h>

using namespace std;

class Base {

cout << “子类的成员函数调用\n”;

}

int main() {

//但是关键的是 子类函数只要和继承函数发生同名情况 就会屏蔽掉继承的成员函数 这会意味着继承的func(int a)也会被屏蔽 哪怕发生了重载

//son.func(100); //取消注释会报错 有重载也会被屏蔽 需要加作用域强调这是继承

son.Base::func(100);

}

继承同名静态成员处理

注意静态成员的两种调用方式 对象.成员 和 类名::成员

#include<bits/stdc++.h>

using namespace std;

}

};

int Son::a = 10;

int main() {//静态成员的访问可以用 . 访问 也可以用类名::访问 因为静态成员属于一整个类 不限于对象了

//下面是用两种静态成员访问方法 来调用静态子类成员(变量、函数)和静态继承成员(变量、函数) 222

Son son;

cout << “son下的a=” << son.a << endl;

cout << “son下的a=” << Son::a << endl;

cout << “son继承的Base的a=” << son.Base::a << endl;

多继承

多继承是指一个子类可以继承多和父类 认多个爹

class子类:继承类型 父类,继承类型 父类2,…{};

多继承时会经常遇到多个父类里定义了同名的成员 导致继承时不明确 就像子类定义的成员和继承的成员同名的情况处理方式一样 用上 类名:: 明确作用域就好了

#include<bits/stdc++.h>

using namespace std;

class BaseA {

public:

int m_a=1;

void func() {

cout << “调用了继承BaseA的func()\n”;

}

};

class BaseB {

public:

int m_a=2;

void func() {

cout << “调用了继承BaseB的func()\n”;

}

void func(int a) {

cout << “调用了继承BaseB的func(int a)\n”;

}

};

class Son:public BaseA,public BaseB{

public:

int m_a=3;

void func() {

cout << BaseA::m_a << “ “ << BaseB::m_a <<” “<< m_a << endl;

}

};

int main() {

Son son;

son.func();

son.BaseA::func();

son.BaseB::func();

son.BaseB::func(5);

}

继承的向上转型

我们知道子类包含父类的所有成员

这也就说 如果不考虑子类继承父类的隐私成员无法调用的情况，再加上被屏蔽掉子类的独特成员，那么子类和父类的成员构成是一样的

#include<bits/stdc++.h>

using namespace std;

class Base {

public:

void func() {

cout << “调用的是父类的成员函数\n”;

}

};

class Son:public Base {

public:

void func() {

cout << “调用的是子类的成员函数\n”;

}

};

void check(Base &a) {

a.func();

}

int main() {

Son son;

check(son);//把子类对象当作父类对象传入

}

你看看 原本要传的Base类下的对象 但是调用check()时传入了 Son类下的对象

正常输出 没有编译错误

这就是因为设计时允许把子类当作父类传入(传入后发生了把子类独特成员屏蔽的行为,这样照可用内容来看,被当父类传入的子类完全可以当作一个对于父类而言，无法访问的自身成员的对象来使用，这时候被传入的子类和父类可访问的内容完全一样)

然后在编译阶段对象a被读取得到类型是Base 所以编译器调用的是子类中的Base::func() (传入对象确实还是子类,编译器读取的是子类继承父类的Bae::func(),这很正常 就是一个根据类型调用自身还是父类的一个选择而已)

多态

多态（Polymorphism）是指同一个名字可以代表多种不同类型的实体，或者说同一个接口可以有多种不同的实现。

多态分为静态多态和动态多态

静态多态是指编译时就完成的操作 动态多态就是指运行时才完成的操作

前半句就是指 函数重载 运算符重载这样的 静态多态

后半句就是指 虚函数+向上传递 组成的同一函数多个实现的 动态多态

如何构建虚函数来实现动态多态呢 我们稍微对上一个继承的向上转型多加关键字

virtual就可以了

#include<bits/stdc++.h>

using namespace std;

class Base {

public:

virtual void func() {//virtual关键字实现了

cout << “调用的是父类的成员函数\n”;

}

};

class Son :public Base {

public:

void func() {

cout << “调用的是子类的成员函数\n”;

}

};

void check(Base& a) {//Base &a = son

a.func();//a现在是Base下的对象

}

int main() {

Son son;

check(son);//把子类对象当作父类对象传入

}

我们要讲清楚多态的内存实现 就要先明白这个前提

原来没virtual的关键字继承又发生同名的时候 分为三个func 一个是父类的func 一个是子类的func 一个是子类中由父类继承来的func 这个不是父类的原本 而且因为和子类的func同名 导致它被隐藏 这三者的内存地址都不一样

virtual的重写机制

父类前缀virtual的函数在其子类中被写同名函数,不会让继承于父类的函数让出名称(就是避免了就近原则导致继承的func()被隐藏，使得调用继承的func()从func()变成Base::func())来让子类写一份自身的函数,而是被重写一遍实现

也就是说

父类 的virtual func()

在子类里写一遍 func() 这个func()不再是”属于子类 然后把父类继承的同名函数func()给隐藏”的这种形式

而是子类声明的func()就是继承的virtual func() 刚开始两者两个地址 之后继承的func地址被子类func的地址覆盖 丢失了继承func的地址

virtual的作用

void Speak(动物& a) {//一个接口 造成了不同的实现(调用了三个不同的speak)

a.func();

}

编译阶段读到这一行时 看到动物& a 原本默认是a是父类 直接编译时绑定关系(静态绑定)

但是编译器在Speak()形参列表之前 读到了的父类内容时 发现了func()前接virtual关键字 这就让编译器执行了下面这个绑定逻辑：当出现调用父类的func()时 我们先不在编译阶段写死调用继承于父类的Base::func() 到运行时再调用func() 所以编译器读到被当作是父类的对象a 调用func()这一行a.func()时 就执行了这个动态绑定逻辑(区别于原来无virtual时的静态绑定)

重写导致的虚函数表被覆盖

虚函数表里存的是函数的地址，virtual func() 会导致父类在编译阶段 建立一个虚函数指针vfptr 和vfptr指向的虚函数表vftable,子类会继承这个虚函数指针和虚函数表

然后虚函数的重写是直接修改继承的虚函数表的内容(函数的地址) 使继承的func()的地址被修改为子类的func()地址(这就是导致子类当中的继承func和子类func是一个的原因)

也就是涉及了一共三个地址 丢弃了继承的func 地址 实际用两份地址

运行时的向上转型实现虚函数表覆盖

现在运行时读到了

void Speak(动物& a) {//一个接口 造成了不同的实现(调用了三个不同的speak)

a.func();

}

编译器就去调用动物类a的成员函数func() 编译器按照传入后给定的类型认为子类a是父类动物类,但是子类a里没有父类的func,所以去调用的是继承的func

但是编译器看到了子类有虚函数表和虚函数指针 就会用虚函数指针访问虚函数表的方式进行调用 在这之前执行了关键逻辑：

子类的虚函数表的内容中，继承于父类的func() 的地址，被修改成了子类func()的地址

然后实现了 多态。

这个过程本质上就是(被当作父类的)子类调用自己（继承的）的func()罢了(只不过继承的func被修改成了子类特有的func)（丢弃了继承func的地址）

那么有人就问那父类的func()呢 我们的子类虚函数表和父类虚函数表是按值拷贝 因为虚函数表本身不是一个指针 所以就会产生副本

所以子类继承的虚函数表被重写修改 不会导致父类虚函数表变化

不会把父类func的地址给搞丢 放心直接调用就行。 我们怎么调用父类的func()呢

那我们就声明一个父类对象 然后以。的方式访问即可 或者用Base::

纯虚函数与抽象类

上一节的动物说话例子中利用虚函数实现了接口与实现分离，但是我们发现这个虚函数内部的cout << “动物在说话\n”;内容没有任何意义 内部直接可以空写。

也就是可以写为 这样的形式

但是如果为了重写需要类型是int 那么还要写为 virtual int func(){rrturn 0}的形式 太麻烦了 所以我们规定 **virtual 类型 func()=0 **就是声明为纯虚函数

注意：纯虚函数也可以再外部通过 类名::纯虚函数名{实现内容}实现类外部添加实现 但是这就是脱裤子放屁 直接用虚函数也能起到这个效果

1不实现任何功能的虚函数叫做纯虚函数

2至少包含一个纯虚函数的类叫做抽象类

3抽象类不能直接定义对象 因为抽象类的纯虚函数没有实现 导致类不完整 编译器不能实例化它

4如果你想让子类可以定义对象就需要把所有继承的纯虚函数都要重写 要不然子类也会因为继承成为抽象类

解决子类析构调用不到的问题

#include<bits/stdc++.h>

using namespace std;

class 房东 {

public:

房东() {

cout << “房东租房子给租客\n”;

}

~房东() {

cout << “房子收走喽\n”;

}

};

class 租客:public 房东 {

public:

int* 空调;

租客() {

cout << “租客装了一个空调\n”;

空调 = new int(10);

}

~租客() {

if (空调 != NULL) {

delete 空调;

空调 = NULL;

cout << “空调拆下来带走了\n”;

}

}

};

int main() {

房东* a = new 租客;//在堆区创建租客对象 层层构造 先走父类构造 然后走子类构造 房东*a就是建立一个指针 a不是对象 所以两个构造就走一遍

delete a;

//没有空调析构的输出 空调这个占用堆区内容的指针忘了释放了

}

向上转型没走租客的析构 但是走了租客的构造是咋回事呢

因为构造时是层层构造 构造函数因为编译顺序会强制走一遍

但是成员函数 和 析构函数 因为编译器认为a是父类 就光调用父类的成员函数和析构函数 前两节我们为了解决默认调用父类成员函数不调用子类成员函数的情况 我们使用了virtual 关键字 放到函数声明前构成了(纯)虚函数 我们也可以通过这个方式构成(纯)虚析构函数

(纯)虚析构函数 和 (纯)虚函数 的原理完全一样 都是用vfptr 指向vftable

然后重写实现(房东(){}和租客(){}名字不同但也被视为重写)

但是虚析构还会多一步操作 编译器会在子类析构函数里偷偷塞入父类析构的代码 这样重写后不仅仅实现子类的析构调用还能实现父类的析构调用

输出结果为

父类子类的析构都实现了输出

纯虚析构函数需要声明也需要实现的矛盾

和虚函数不同 虚析构函数需要调用父类和子类 这就导致了父类也必须需要写析构的实现

这就会出现一个矛盾 如果把写纯虚析构 纯虚析构会调用自己和子类析构的实现 但是它自身又没有实现 调用无实现的内容会发生错误

所以我们就用 类名::~纯虚析构函数名(){实现内容} 在类外实现补充实现

�G这为啥不直接用 虚析构函数 非要用纯的呢？

实际上我们在开发中会想实现这样的功能 我们想要把一个没有纯虚函数的类 变成抽象类 还不添加纯虚函数 那就用纯虚析构函数 来实现 纯虚析构必须需要在外部有实现 这就能让一个都有实现的类 变成抽象类

那①啃槲龉购偌由侠嗤馐迪�和②啃楹偌由侠嗤馐迪�有啥区别呢？

因为子类的析构一般也必须要写 这样会都导致子类的继承的析构被重写 子类不是抽象类

纯虚函数加类外实现仍然会让子类和父类一样都是抽象类 子类必须要重写成员函数

所以比起来重写函数 我还是喜欢重写必须要写的析构 所以①还有点用 ②是真没用

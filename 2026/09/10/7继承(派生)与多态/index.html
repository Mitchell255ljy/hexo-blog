1P07 继承(派生)与多态

发表于2026-09-10|更新于2026-09-10
|浏览量:

继承（派生）

在复制的原理上：拷贝和继承之间的区别

  • 拷贝是对象层面的操作，指用一个已存在的对象，去创建另一个同类的新对象，并将成员变量的值复制过去。
  • 继承是类层面的关系，指一个类（子类）复用另一个类（父类）的成员（属性和方法），并可以扩展或重写。其中子类又叫派生类，父类又叫基类。

所谓的复用是指：继承是在编译时，把父类的所有成员定义直接「复制粘贴」到子类中！ 这样就能减少相同代码的重复书写。

子类继承父类内容的语法

子类是这样声明的：class 子类 : 继承类型 父类 { 子类的专属内容 };

在访问的方式上：友元和继承之间的区别

友元函数、友元类等并不是被访问类的内部成员，但是它被特别授权，可以访问甚至修改被访问类的所有内容，彻底破坏了封装，内部成员支持任意修改。

继承则不同：子类继承父类后所做的修改，并不会影响父类原本的内容，因为继承相当于在子类中新建了一份父类的成员副本，修改的是这份副本，而非父类本身。

继承时，子类无论如何都无法修改父类对象的内容！

JAVA 里没有友元的概念。

这是因为继承是成员的直接复制粘贴，子类里的内容实际上也有：

就相当于指针变量 家产b 在子类里又建立了一遍，和父类的指针变量 家产b 没有啥关系。

保护访问权限与继承类型

protected 保护访问权限：限制「类内部」和「子类」访问

继承类型也分三种，关键字和访问权限一样

下面是继承类型造成的继承特性：

  1. 三种继承方式，子类都只能继承父类的公共访问权限和保护访问权限的内容；
  2. 公有继承：得到的公有内容和保护内容的访问权限在子类当中不变；保护继承：得到的公有内容和保护内容的访问权限在子类当中全变为保护；私有继承：得到的公有内容和保护内容的访问权限在子类当中全变为私有。

继承走的顺序和前面的友元根本逻辑一样

继承成员和子类声明的成员同名处理

当子类继承父类的 m_a 时，m_a 就能调用；但是在子类里再声明 int m_a 会怎么样呢？

那么原来默认表示「子类继承成员」的 m_a，现在变成表示「子类自身成员」m_a 了。当我们想要对子类继承来的 m_a 做操作时，就需要再明确是父类的继承，用 父类名:: 来明确。

注意：这个对父类继承来的 m_a 操作，不是对原父类成员 m_a 做操作——继承来的 m_a 是父类成员 m_a 的副本。别被「父类成员 m_a」「子类继承成员 m_a」「子类成员 m_a」搞晕了。

当然对于成员函数也是一样的

注意静态成员的两种调用方式：对象.成员 和 类名::成员

当然静态成员函数和上一章的普通成员函数一样，即使发生重载但同名，子类仍然会把父类继承的给隐藏。

多继承

多继承是指一个子类可以继承多个父类，「认多个爹」

多继承时会经常遇到多个父类里定义了同名的成员，导致继承时不明确。就像「子类定义的成员和继承的成员同名」的情况处理方式一样，用上 类名:: 明确作用域就好了。

虚继承（可以不学，不实用还很少出现）

在 C++ 中，实现这个机制的关键字就是 virtual。

这样写之后，基类就被称为「虚基类」。编译器在子类中会悄悄地加入一个叫做 vbptr（虚基类指针）的东西。这个 vbptr 的特点在于：

它不直接指向虚基类的位置，而是指向一个位于对象外部的「虚基类表」（vbtable），表中存储的是当前对象相对于虚基类的偏移量，然后用当前类的地址加上 vbptr 获取到的偏移量，编译器就能计算出虚基类的实际地址（用 虚基类:: 访问其成员时就会调用虚基类指针获取偏移，然后临时计算继承的地址），最终访问到的是继承来的成员。

？？你的意思是说，这样老半天我们访问的是原来可以直接访问的继承成员？？

虚继承就是通过一个更复杂的逻辑来访问从父类继承来的成员（不是父类原本的成员），但是能实现继承成员放到共有的内存上，让大家用 vbptr 都能访问——用一份的继承成员来实现共享。

但是我们原来直接能访问继承成员，啥情况才用得上这个虚继承呢：

  1. 你想实现继承成员共享；
  2. 菱形继承为了减少继承成员时需要用到虚继承。

继承的向上转型

我们知道子类包含父类的所有成员

这也就是说，如果不考虑「子类继承父类的隐私成员无法调用」的情况，再加上被屏蔽掉子类的独特成员，那么子类和父类的成员构成是一样的。

你看看：原本要传 Base 类下的对象，但是调用 check() 时传入了 Son 类下的对象。

正常输出，没有编译错误

这就是因为设计时允许把子类当作父类传入（传入后发生了把子类独特成员屏蔽的行为，这样从可用内容来看，被当父类传入的子类完全可以当作一个「对于父类而言无法访问的自身成员」的对象来使用，这时候被传入的子类和父类可访问的内容完全一样）。

然后在编译阶段对象 a 被读取得到类型是 Base，所以编译器调用的是子类中的 Base::func()（传入对象确实还是子类，编译器读取的是子类继承父类的 Base::func()，这很正常，就是一个「根据类型调用自身还是父类」的选择而已）。

多态

多态（Polymorphism）是指同一个名字可以代表多种不同类型的实体，或者说同一个接口可以有多种不同的实现

多态分为静态多态和动态多态

  • 静态多态：编译时就完成的操作；
  • 动态多态：运行时才完成的操作。

前半句就是指「函数重载、运算符重载」这样的静态多态；后半句就是指「虚函数 + 向上传递」组成的同一函数多个实现的动态多态。

如何构建虚函数来实现动态多态呢？我们稍微对上一个「继承的向上转型」多加关键字 virtual 就可以了。

甚至可以

我们要讲清楚多态的内存实现，就要先明白这个前提

原来没 virtual 的关键字、继承又发生同名的时候，分为三个 func：一个是父类的 func，一个是子类的 func，一个是子类中由父类继承来的 func——这个不是父类的原本，而且因为和子类的 func 同名，导致它被隐藏。这三者的内存地址都不一样。

virtual 的重写机制

父类前缀 virtual 的函数在其子类中被写同名函数，不会让继承于父类的函数让出名称（就是避免了「就近原则导致继承的 func() 被隐藏，使得调用继承的 func() 从 func() 变成 Base::func()」），来让子类写一份自身的函数，而是被重写一遍实现。

也就是说

父类的 virtual func()，在子类里写一遍 func()，这个 func() 不再是「属于子类、然后把父类继承的同名函数 func() 给隐藏」的这种形式，而是子类声明的 func() 就是继承的 virtual func()。刚开始两者两个地址，之后继承的 func 地址被子类 func 的地址覆盖，丢失了继承 func 的地址。

virtual 的作用

但是编译器在 Speak() 形参列表之前，读到了父类内容时，发现了 func() 前接 virtual 关键字，这就让编译器执行了下面这个绑定逻辑：当出现调用父类的 func() 时，我们先不在编译阶段写死调用继承于父类的 Base::func()，到运行时再调用 func()。所以编译器读到「被当作是父类的对象 a 调用 func() 这一行 a.func()」时，就执行了这个动态绑定逻辑（区别于原来无 virtual 时的静态绑定）。

重写导致的虚函数表被覆盖

虚函数表里存的是函数的地址，virtual func() 会导致父类在编译阶段建立一个虚函数指针 vfptr 和 vfptr 指向的虚函数表 vftable，子类会继承这个虚函数指针和虚函数表。

然后虚函数的重写是直接修改继承的虚函数表的内容（函数的地址），使继承的 func() 的地址被修改为子类的 func() 地址（这就是导致子类当中的继承 func 和子类 func 是一个的原因）。

也就是涉及了一共三个地址，丢弃了继承的 func 地址，实际用两份地址。

运行时的向上转型实现虚函数表覆盖

现在运行时读到了：

编译器就去调用动物类 a 的成员函数 func()。编译器按照传入后给定的类型认为子类 a 是父类动物类，但是子类 a 里没有父类的 func，所以去调用的是继承的 func。

但是编译器看到了子类有虚函数表和虚函数指针，就会用虚函数指针访问虚函数表的方式进行调用。在这之前执行了关键逻辑：子类的虚函数表的内容中，继承于父类的 func() 的地址，被修改成了子类 func() 的地址，然后实现了多态。

这个过程本质上就是「（被当作父类的）子类调用自己（继承的）的 func()」罢了（只不过继承的 func 被修改成了子类特有的 func，丢弃了继承 func 的地址）。

那么有人就问：那父类的 func() 呢？我们的子类虚函数表和父类虚函数表是按值拷贝，因为虚函数表本身不是一个指针，所以就会产生副本。所以子类继承的虚函数表被重写修改，不会导致父类虚函数表变化，不会把父类 func 的地址给搞丢，放心直接调用就行。我们怎么调用父类的 func() 呢？那就声明一个父类对象，然后以 . 的方式访问即可，或者用 Base::。

多态是「接口与实现分离」这一原则得以实现的关键机制

我们的动物、大狗、小鸡这个例子中，在功能上，动物类就是接口，其内部 func() 没有得到任何的使用，只是为了给大狗、小鸡、企鹅类这些实现提供一个 动物类.func() 的调用方式而已。

也就是说，我们把接口和实现写到了不同的类中

  • 创建子类继承父类并实现重写功能，这样父类就作为接口；
  • 子类作为实现，以后要添加额外功能时就不用动父类了。

但是如果为了重写需要类型是 int，那么还要写为 virtual int func() { return 0; } 的形式，太麻烦了。所以我们规定 virtual 类型 func() = 0; 就是声明为纯虚函数。

注意：纯虚函数也可以在外部通过 类名::纯虚函数名() { 实现内容 } 实现类外部添加实现，但这就是「脱裤子放屁」，直接用虚函数也能起到这个效果。

  1. 不实现任何功能的虚函数叫做纯虚函数；
  2. 至少包含一个纯虚函数的类叫做抽象类；
  3. 抽象类不能直接定义对象，因为抽象类的纯虚函数没有实现，导致类不完整，编译器不能实例化它；
  4. 如果你想让子类可以定义对象，就需要把所有继承的纯虚函数都重写，要不然子类也会因为继承成为抽象类。

虚析构与纯虚析构

解决「子类析构调用不到」的问题

向上转型没走租客的析构，但是走了租客的构造是咋回事呢？

因为构造时是层层构造，构造函数因为编译顺序会强制走一遍。但是成员函数和析构函数，因为编译器认为 a 是父类，就光调用父类的成员函数和析构函数。前两节我们为了解决「默认调用父类成员函数、不调用子类成员函数」的情况，使用了 virtual 关键字放到函数声明前，构成了（纯）虚函数。我们也可以通过这个方式构成（纯）虚析构函数。

（纯）虚析构函数和（纯）虚函数的原理完全一样，都是用 vfptr 指向 vftable，然后重写实现（~房东(){} 和 ~租客(){} 名字不同但也被视为重写）。

但是虚析构还会多一步操作：编译器会在子类析构函数里偷偷塞入父类析构的代码，这样重写后不仅仅实现子类的析构调用，还能实现父类的析构调用。

纯虚析构函数需要声明也需要实现的矛盾

和虚函数不同，虚析构函数需要调用父类和子类，这就导致了父类也必须需要写析构的实现。这就会出现一个矛盾：如果把写纯虚析构，纯虚析构会调用自己和子类析构的实现，但是它自身又没有实现，调用无实现的内容会发生错误。

所以我们就用 类名::~纯虚析构函数名() { 实现内容 } 在类外实现补充实现。

那这为啥不直接用虚析构函数，非要用纯的呢？

实际上我们在开发中会想实现这样的功能：我们想要把一个没有纯虚函数的类变成抽象类，还不添加纯虚函数，那就用纯虚析构函数来实现。纯虚析构必须需要在外部有实现，这就能让一个都有实现的类变成抽象类。

那①纯虚析构函数再加上类外实现，和②纯虚函数再加上类外实现，有啥区别呢？

因为子类的析构一般也必须要写，这样都会导致子类继承的析构被重写，子类不是抽象类。纯虚函数加类外实现仍然会让子类和父类一样都是抽象类，子类必须要重写成员函数。

所以比起来重写函数，我还是喜欢重写必须要写的析构。所以①还有点用，②是真没用。

1C01 工作流模型与文件处理指令

源文件的概念

打开编译器呈现源代码的文件

对于c++来说就是后缀名为.cpp的文件

编译到运行的工作流模型

一、整体流程

一个 C++ 程序从编写到运行，分为三个阶段：编译阶段、汇编阶段、链接阶段，最后进入运行阶段。

二、编译阶段

编译阶段，是编译器把源代码翻译成汇编代码的过程。

编译 = 将源代码（人类可读的文本）翻译成汇编代码（CPU 指令的文本表示）的过程。编译器在这里起到翻译的作用，把 C++ 代码翻译成汇编语言，为后续的汇编阶段做准备。

编译阶段又分为两步：

注意：编译的输出是汇编代码，是可读的文本，不是二进制文件（机器码）

三、汇编阶段

汇编阶段，是汇编器把汇编代码翻译成机器码的过程。

汇编 = 将汇编代码（.s，文本）翻译成机器码（.o，二进制）的过程。汇编器把汇编语言逐条翻译成 CPU 能直接执行的指令，生成目标文件。

这个目标文件就是“链接前的材料”：它已经是机器码了，但还不能直接运行，因为它缺少外部函数的地址，也缺少程序入口。

举个例子：

假设你有两个文件：

add.cpp：里面定义了 add() 函数。

main.cpp：里面定义了 main() 函数，并在其中调用了 add(3, 8) 和 cout。

经过编译和汇编后，你会得到两个独立的目标文件：

add.o：里面是 add() 函数的机器码。

main.o：里面是 main() 函数的机器码，其中调用了 add() 和 cout。

此时，这两个 .o 文件都不能直接运行。

原因一：add.o 没有程序入口。 程序要运行，必须有一个入口，也就是 main() 函数。而 add.o 里只有 add()，没有 main()。操作系统加载程序时，找不到入口，不知道从哪开始执行。所以 add.o 单独存在时，只是一个“函数仓库”，不是“可运行程序”。

原因二：main.o 缺少外部函数的地址。 main.o 里有 main()，也有调用 add() 和 cout 的指令。但：

add() 的实现在 add.o 里，main.o 编译时还不知道 add() 在内存里的地址。

cout 的实现来自标准库STL。标准库大部分是模板库模式（比如 vector、map、string），只有少部分像 cout、cin 这种才需要链接库文件，属于类似 SDK 的调用模式。这类需要链接的库，模式都一样：头文件给声明，库文件（lib 或 dll）给实现，链接器把两者拼起来。编译器默认已经引入了 iostream 对应的 lib 和 dll，所以你感觉不到这个过程。

即使我们 #include 了这个头文件，也只是把 cout 的声明复制到了 main.cpp 内，真正的实现还在 lib 或 dll 里。所以 main.o 在编译时，更不知道 cout 的实现到底在内存的哪个地址。

所以，main.o 里调用 add() 和 cout 的地方，地址都是空着的（重定位项），等着链接器来填。

我们刚才的讨论可能还比较抽象，不容易直观感受到标准库里两种模式的区别。不如直接动手验证：

新建一个 C++ 项目，输入两个头文件：

然后分别对着这两个头文件，查找它们的实现：

iostream：你点进去看，会发现里面没有实现逻辑，只有 cout、cin 的声明（extern 声明）。真正的实现在 lib 或 dll 里。

vector：你点进去看，会发现里面有完整的实现逻辑，比如动态扩容、元素插入、迭代器操作等，全都写在头文件里。

这就是标准库里两种模式的直观区别：大部分是模板库模式（如 vector），少部分是需要链接的模式（如 cout）。

链接阶段，是把多个目标文件（.o）和系统库拼装成可执行文件的过程。

五、运行阶段

运行阶段，是操作系统加载可执行文件，机器开始执行指令的过程。

此时程序已经是完整的机器码，操作系统把它加载到内存，CPU 逐条执行，程序开始运行。

在 Visual Studio、VS Code、CLion 这类 IDE 里，你点一下“运行”三角按钮，程序就跑起来了。你感觉不到编译过程，是因为 IDE 在背后自动帮你做完了全部步骤：

而你在命令行里手动敲 g++，就是把这些步骤手动做一遍。

四个编译阶段对应的 g++ 指令

当然，g++ 不是无脑一步步做，而是根据你给它的输入文件类型，决定从哪一步开始：给 .cpp 就从预处理开始，给 .i 就从编译开始，给 .s 就从汇编开始，给 .o 就从链接开始。前面没做的会自动补上，前面已经做完的不会重做。然后一路做到你用 -E、-S、-c 指定的那一步为止。

比如：

g++ -c hello.cpp -o hello.o：输入是 .cpp，起点是预处理，终点是汇编（因为 -c），所以它自动做完预处理 + 编译 + 汇编，一步得到 .o。

g++ hello.o -o hello：输入是 .o，起点是链接，终点是链接，所以它只做链接，直接得到可执行文件。

g++ hello.cpp -o hello：输入是 .cpp，起点是预处理，终点是链接（没加 -E、-S、-c），所以它自动做完全部四步。

预处理指令

以 # 开头的指令称为预处理指令（或源文件文本处理指令）。

#include 的作用

#include  或 #include “text” 的作用是： 将指定文件（text）的内容复制到当前文件中，并替换掉该 #include 指令本身，从而实现外部文件的插入。

#include <> 与 #include “” 的区别

此外，#include “” 也可以通过编译器设置添加额外的搜索路径。

什么是头文件/预处理文件？

以 #include<> 指令给源文件在预处理阶段做补充的文件，叫做头文件。

在处于预处理阶段时，#include<头文件> 这个文本处理指令，就是为了把头文件复制粘贴过来。

比如 #include<stdio.h> 这个形式，就是把 stdio.h 这个头文件调用过来。

#include 是 C/C++ 语言中的预处理指令，用于在编译前将指定文件（通常是头文件）的内容插入到当前源代码文件中，以实现代码复用和模块化开发。

下面是常见的头文件以及包含功能：

提供输入输出流功能，包含核心对象如：

cin：标准输入流（键盘输入）

cout：标准输出流（控制台输出）

cerr / clog：错误和日志流

支持运算符 << 和 >> 进行格式化 I/O 操作

提供数学函数库，包含：

基本运算：sqrt()、pow()、abs()

三角函数：sin()、cos()、tan()

对数/指数：log()、exp()

所有函数均支持浮点数运算

包含常用算法操作：

排序：sort()、stable_sort()

查找：find()、binary_search()

数值处理：max()、min()、accumulate()

适用于容器（如数组、vector）的泛型算法

<stdio.h>

C 语言标准 I/O 库，提供：

printf() / scanf()：格式化输入输出

文件操作：fopen()、fread()

在 C++ 中通常用 替代以符合命名空间规范

常用万能头

万能头文件就是包含很多 #include<头文件> 的头文件。

我们来推演一下：

万能头文件 a.h 写了 #include<b.h>、#include<c.h>、#include<d.h>。

那么源文件中执行 #include<a.h>，就是把 #include<b.h>、#include<c.h>、#include<d.h> 插入到这个位置。

然后再处理三个 #include 指令，那么就把 b.h、c.h、d.h 的内容都给插入进来了。

在不做大型项目时，我们一般直接调用万能头（包含对应的很多头文件，相当于整合工具箱的工具箱），来避免用到的头都 include 一遍，来节省时间。

但是大型项目尽可能用啥 include 啥，不要乱用万能头。不然你会发现声明一个变量 y3，结果会报错，因为 y1、y2、y3 是保留标识符，他们是一个功能函数的名字。

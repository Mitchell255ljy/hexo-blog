重载

重载的核心就是：同一个名字（函数名或运算符），对应多种不同的实现，编译器根据上下文自动选择正确的那个,这样我们实现了同名但实现内容不同的应用。

重载分为 函数重载和 运算符重载

函数重载是在同一作用域内，定义多个同名函数，通过参数列表的不同来区分。

运算符重载是为自定义类型（类、结构体）重新定义运算符的含义，使其支持与内置类型相似的运算语法。

我们使用运算符重载的根本原因，是为了让自定义类型（对象）支持运算和逻辑表达，从而获得与内置类型一致的语义完整性,让程序员能够以自然的方式操作自定义类型对象。

四则运算符的重载(双目运算符)

operator运算符重载函数的参数列表为什么最多两个参数？

运算符的本质是表达两个对象之间的关系，三个及以上的关系可以拆分成多次二元运算，所以不需要设计成支持三个参数。

四则运算(双目) 运算符重载声明语法

类名成员函数

类名 operator运算符名(类名&对象){}

类名全局函数

类名operator 运算符名(类名&对象1,类名&对象2){}

operator 关键字是告诉编译器：我要为这个类型定义运算符的行为。编译器会帮我们做语法转换:

当这个运算符重载函数为成员函数时

就会发生 对象 运算符名 对象2 一》 对象.operator运算符名(对象2)

当这个运算符重载函数为全局函数时

就会发生 对象1运算符名 对象2 一》 operator运算符名(对象1,对象2)

#include<bits/stdc++.h>

using namespace std;

class MyClass {

public:

int a=0;

int b=0;

MyClass operator+(const MyClass&p) {//类型为MyClass的成员函数 需要构建临时对象来实现返回MyClass类型

MyClass temp;//创建临时对象temp

temp.a =this->a+ p.a;

temp.b =this->b+ p.b;

return temp;//先返回临时对象的值

}//temp生命周期结束

~MyClass(){

cout << “有人调用了析构函数！” << endl;

}

};

MyClass operator+(const MyClass& m, const MyClass& n) {//再声明一个全局类名函数 这里的全局operator+双参数和 类内成员函数operator+的单参数发生了函数重载

MyClass temp;

temp.a = m.a + n.a;

temp.b = m.b + n.b;

return temp;

}

int main() {

MyClass a, b,c,d,e,f;

a.a = 10;

a.b = 10;

b.a = 11;

b.b = 12;

c = a.operator+(b);//单参数 成员函数运算符重载的根本原理

d = a + b;//编译器对于operator的包容性 隐式转化

cout <<”对象c的两成员变量值 “ << c.a <<” “ << c.b << endl<<”对象d的两成员变量值 “ << d.a << “ “ << d.b << endl;

e = operator+(a, b);//双参数 全局函数运算符重载的根本原理

f = a + b;

cout << “对象e的两成员变量值 “ << e.a << “ “ << e.b << endl << “对象f的两成员变量值 “ << f.a << “ “ << f.b << endl;

}

这里d=a+b 和 f=a+b 每一个a+b都可以引述转化后对应两个 运算符重载函数(全局和成员) 但是我这里运行没报警(按理说是没法区分对应哪个运算符重载函数的)

这是因为我的编译器给两种运算符重载函数有了优先级排序

如果你的编译器报错 请屏蔽其中一种重载函数 然后把相关的 隐式转化前的调用行给注释掉就行了

根据上面的这个加法运算符重载的例子 我们可以替换operator关键字后的运算符名 和运算符重载函数里的规则 就可以实现 减法、乘法、除法的运算符重载

左移运算符重载(双目运算符)

我们想要实现 cout<<对象 怎么办呢

对源文件里的cout选定后按F12转到声明发现

cout是ostream(输出流类)下的一个对象

输出流类内禁用了拷贝构造函数 这导致了就像前向声明的成员类一样 只能指针调用和传引用调用 我们这里稍微分析它俩为啥会导致一个调用规则

前向声明对象 因为没有初始内容 直接传值调用 会经过拷贝构造 拷贝构造拷贝空？显然会错误;

输出流类的拷贝构造直接被禁用了 用值拷贝会直接崩溃

既然cout是一个对象 那么就支持operator里填入(const ostream&cout)了

值得注意的是我们的<<重载函数内部仅实现输出功能 并不需要返回对象使得给等式右端赋值之类的操作

使用void形式就可以

所以在这里我们设计的运算符重载函数的形式为(待议)

成员函数

void operator运算符名(类名&对象){}

全局函数

void operator 运算符名(类名&对象1,类名&对象2){}

#include<bits/stdc++.h>

using namespace std;

class MyClass {

public:

int m_a = 100;

int m_b = 200;

void operator<<(ostream&cout) {//流对象前不能接const 里面有很多需要被修改的状态 流对象 需前接& 不能直接进行值拷贝

cout<<”成员函数输出： “ << “m_a=” << m_a << “ m_b=” << m_b;

}

};

void operator<<(ostream&cout,const MyClass&a) {

cout <<”全局函数输出： “<< “m_a=” << a.m_a << “ m_b=” << a.m_b;

}

int main() {

MyClass a;

cout << a;//全局函数是由 operator<<(cout,a) 简化为是 cout<<a的形式

cout << endl;

a << cout;//成员函数是由 a.operator<<(cout) 简化为是 a<<cout的形式

}

所以我们一般重载函数写全局函数的形式(cout<<调用) 而不是成员函数的形式(<<cout调用)

但是我们在调试时发现链式调用(cout<<a<<endl<<b;)不支持

所以我们在例子里是cout<<a; cout<<endl; cout<<b;

回顾返回*this指针 实现成员函数的链式调用可知

如果想要支持<<重载的链式调用 我们在重载函数结尾需要 return cout;

这样就能使得

cout<<a<<endl<<b; 逐步变为

cout<<endl<<b; (cout<<a变为了cout)

cout<<b; (cout<<endl又变为了cout)

从而实现了连续输出a、endl、b

对应的 为了能返回cout(ostream类下的对象)

我们需要把重载函数类型void改为 ostream

但是输出流类又不能直接传值 所以需要为引用类 ostream&

故最终设计的运算符重载形式为

成员函数

ostream& operator运算符名(类名&对象){} 不推荐

全局函数

ostream& operator 运算符名(类名&对象1,类名&对象2){}

语法转换为

对象1 运算符名 对象2 一》 operator 运算符名(对象1,对象2)

#include<bits/stdc++.h>

using namespace std;

class MyClass {

public:

int m_a = 100;

int m_b = 200;

};

ostream& operator<<(ostream&cout,const MyClass&a) {

cout <<”全局函数输出： “<< “m_a=” << a.m_a << “ m_b=” << a.m_b;

return cout;

}

int main() {

MyClass a,b;

int biao[] = { 1,2,3 };

cout << a<<” “ << biao[0]<<” “ << b<<endl;//完成了链式引用

clog << a << “ 字符串 “ << endl;//clog也是iostream头里声明的输出流对象

以运算符重载函数的形参列表显然支持clog、cerr

}

在cout << a<<” “ << biao[0]<<” “ << b<<endl;//完成了链式引用 这里

发生了两种cout的转化 第一个cout<<a是重载的函数实现的 第二三四都是原版cout<< 第五是重载 第六是原版cout<<endl

递增运算符重载(单目运算符)

普通变量和递增运算符++组合方式 区分为前置递增 后置递增

后置递增 递增符放在变量a后面 形式为a++

int a=5;

cout<<a++<<endl;//输出5 先输出a 后对a自增

cout<<a<<endl;//输出6

前置递增 递增符放在变量a前面 形式为++a

Int a=5;

cout<<++a<<endl;//输出6

递增运算符 和四则运算、左移运算符不同

它的运算仅需要一个变量就可以 这导致了 单目运算符的成员重载函数形参列表没有必要再添加东西了

成员重载函数也就是这样的形式

MyClass operator++(空){} 没有形参

全局重载函数是这样声明

MyClass operator++(MyClass&obj){} 一个形参

我们一般把单目运算符重载写为成员函数 我们下面就不再讨论单目运算符重载函数的全局写法

设计者对规定单目运算符语法转换为

单目运算符 对象 一》operator单目运算符 对象

比如说

!a 一》 operator!a()

++a 一》opertator++a()

a 一》operatora()

还规定 转换语法有

对象 单目运算符 一》 operator单目运算符(int) 哑元int编译器自动写入

形参列表里多加了一个哑元int 表示我们把单目运算符放到对象后面

比如说

a++ 一》operator++(int)

#include<bits/stdc++.h>

using namespace std;

class MyClass {

public:

int m_a=0;//成员变量初始值为0

//重载前置递增运算符

MyClass& operator++() {

m_a++;

return *this;

}

//重载后置递增运算符

MyClass operator++(int) {//int哑元 有两个作用 一个是为了区分前置和后置 实现重载 编译器为了迎合这种情况 设置了习惯 加入哑元之后就会变成后置递增的显示

MyClass temp = *this;

m_a++;

return temp;

}

};

ostream& operator<<(ostream& cout, MyClass other) {// 左移运算符重载函数推荐写法

cout << other.m_a;

return cout;

}

int main() {

MyClass a,b,c,d;

cout << ++a << “ “ << a << endl;;

cout << b++ << “ “ << b << endl;

cout << ++++c << “ “ << c << endl;

cout << d++++++++++++++++++++++++++++ << “ “ << d << endl;//后置递增不是返回引用 仅在第一次的++上作用到了d对象

}

你发现了 对于前置递增重载函数 为啥是引用类名函数呢

为啥后置递增重载函数 为啥是非引用类名函数呢

对前置重载是引用类的疑问:

前置重载函数是成员函数 里面的m_a肯定被识别为对象a的成员了啊 一般的非引用类名函数 也是直接对对象a的成员进行操作 不会把操作执行到拷贝的副本对象上去 所以非引用类名函数是可以正常执行前置递增运算符重载的

但是有特例 如果进行++(++a)操作呢

先进行(++a)运算 若是非引用类 那么返回的是对象a的副本 再次的++导致把第二次的++自增到了一个神秘对象上 导致a就自增了一次

假设m_a的初始值为0

cout<<++(++a) 输出2

cout<<a 输出1

而我们返回类型是引用类的话 那么就可以连续返回a对象本身

对后置重载为啥不能像前置重载一样用传引用呢

因为看后置重载内容 如果返回类型是引用 那么我们就是返回的临时对象temp 再走完这个重载函数后 temp就会被销毁

这时候就会出现未定义行为

所以后置递增函数不支持(a++)++的连续自增

假设m_a的初始值为0

cout<<(a++)++ 输出2

cout<<a 输出1

事实上 原本的递增运算符也是这样的特性

你会发现你的编译其对于int类型的变量a ++++a支持 但a++++报错！

赋值运算符重载

编译器支持 对象1=对象2这样调用赋值运算符

进行成员逐个拷贝操作

所以一般来说对于

不包含指针成员的简单类直接调用默认的赋值运算符操作即可

但是要是对象要是包含指针成员 我们根据指针成员在堆区上构造的默认习惯 和每个成员析构时delete关键字的调用情景可知 这样会出现指针变量浅拷贝照成的双重释放问题

运行后得到

重复释放（double free） 贝シ⒌拇砦�

这时候我们就要实现深拷贝的赋值运算符重载函数

#include<bits/stdc++.h>

using namespace std;

class MyClass {

public:

int* 指针变量;

MyClass(int a) {

指针变量=new int(a);

}

~MyClass() {

delete 指针变量;

指针变量 = NULL;

}

MyClass& operator=(MyClass&other) {//你知道为啥是 返回类型是 引用类(MyClass&)吗 如果是按值返回(MyClass) 那么就会return 当前对象的副本

//副本创建时就会 走按成员逐个赋值的拷贝构造,导致副本的指针变量也是和原本成员变量也是一个堆内存 析构会导致重复释放

if (指针变量!=NULL) {//我们 a=b 重载时a已经有值了 要先释放a的内存

//要是不用delete释放a的内存 就会给a绑上新的内存 导致a对原内存失去控制 无法再释放原内存 导致原内存一直被占用 照成内存泄露

delete 指针变量;

指针变量 = NULL;

}

指针变量 = new int(other.指针变量);//顺序是 先执行.的访问成员 再执行解引用

return *this;//这里有renturn 语句 上一章的深拷贝没有return 不会创建副本 不用引用类也不会照成重复释放的问题

}

};

int main() {

MyClass obj(2);

cout << *obj.指针变量<<endl;

MyClass obj2(3);

obj = obj2;

cout << *obj.指针变量<<endl;

MyClass obj3(4);

obj = obj2 = obj3;

cout << *obj.指针变量 << *obj2.指针变量 << *obj3.指针变量;

}

你发现了 为啥深拷贝函数里没有赋值重载函数中的这一部分呢:

这样不会导致上一章的例子内存泄露吗？

函数调用运算符重载

函数调用运算符() 的重载函数声明 operator()(形参列表){} 仅支持成员函数形式声明 不支持全局函数声明

为啥这样规定呢

因为对象a的 operator()(int b){}

发生调用时的转化是这样的形式 a(b) 一》 a.operator()(b) 映射关系非常清晰

和前面的双目运算符的调用转化不一样 不是a接运算符接b发生转化(也就是a()b的形式)

而是a(b) 运算符里套入参数b

如果能函数调用运算符重载函数是全局函数的形式 那么调用需发生这样的转化

a(b) 一》 operator(a,b) 这样需要规定a是对象

可以声明operator()(对象a,int b)的重载函数形式,但是为啥没这样办呢

函数调用运算符重载函数的形参列表的参数按需定义

和普通函数调用形式一模一样 我们称 类中重载函数调用运算符() 为仿函数

#include<bits/stdc++.h>

using namespace std;

class MyPrintf {

public:

void operator()(string str) {

cout << str;

}

};

class MyDist {

public:

double operator()(double x, double y) {

return sqrt(x * x + y * y);

}

};

int main() {

MyPrintf my_printf;

MyDist my_dist;

my_printf(“我的输出内容\n”);

cout<<my_dist(1, 1)<<endl;

}

子类构造函数转发

我们平常展示子类父类关系时，会先构造一个父类对象、再构造一个子类对象，用来分别演示各自的调用。但不要误以为：必须先创建一个父类对象，才能创建一个子类对象。

实际上，这个独立的父类对象和子类对象没有任何关系——它们是两个独立的内存实体。

子类对象在创建时，会自动调用父类的构造函数（默认是默认构造），将父类的内容作为子类对象的一部分构建进来。这一切都发生在子类对象创建的过程中，与外部的任何父类对象无关。

也就是说：

外部先创建一个父类对象（无论用什么方式构造，或之后如何修改），都不会影响下一行创建的子类对象内部所包含的父类内容。

直接创建子类对象时，默认会调用父类的默认构造。

那么问题来了：如果我们希望在创建子类对象的同时，也能一并指定子类对象内部那个「父类部分」的初始值，该怎么做？

答案就是：子类构造函数转发（通过初始化列表显式调用父类的含参构造函数）。

先看无子类构造函数转发的情况：

#include<bits/stdc++.h>

using namespace std;

class BASE {

public:

int a;

BASE() {//父类的无参构造函数 子类创建时默认调用父类的无参构造函数来创建父类部分

a = 10;

}

BASE(int x) {//父类的含参构造

a = x;

}

};

class SON : public BASE {

public:

int b;

SON() {

b = 10;

}

SON(int x){

b = x;

}

};

int main() {

BASE base(67);//这个父类对象的a的值是100 但是和后面的子类对象中的父类部分的a没有关系

cout <<”对象base成员a的值为：”<< base.a << endl;//输出67

SON son(1);//b=1

cout << “对象son成员a的值为：” << son.a <<endl;//输出10 说明子类对象son创建时调用的是父类的无参构造函数！

cout<< “对象son成员b的值为：” << son.b <<endl;

//想要修改子类对象中父类部分的成员变量a的值 只能对对象son进行赋值操作

son.a = 100;

cout << “对象base成员a的值为：” << son.a << endl;//输出100

}

我们的son无法在创建时调用父类含参构造函数,son中的父类部分是默认的,需要在用son.来访问修改。

再看利用子类构造函数转发的情况：

#include<bits/stdc++.h>

using namespace std;

class Base {

public:

int m_a=0;

string m_b=”\0”;

char m_c = ‘0’;

Base(int a,string b,char c) {//父类的构造函数

m_a = a;

m_b = b;

m_c = c;

}

};

class Son:public Base {

public:

int m_a=0;

string m_b = “\0”;

Son(int num,string str) :Base(-1, str,’a’) {//这个子类的构造函数 实现了自身的构造 并调用了父类的含参构造 而不再是默认构造了

//第一个形参列表给子类构造用 ：后的第二个形参列表给父类构造用

m_a = num;

m_b = str;

}

void func() {

cout <<”子类自身构造的成员信息: “<< m_a << “ “ << m_b<<endl;

cout << “继承父类的成员信息: “ << Base::m_a << “ “ << Base::m_b <<” “<< Base::m_c;

printf(“\n\n\n”);

}

};

int main() {

Son son(42,”奇妙小信息”); son.func();

}

普通枚举和强制枚举类型

1. 传统 C 枚举 / 普通 enum 的痛点

传统写法：

普通枚举的声明格式是： enum 枚举名 { 常量1, 常量2, … };

例如：

无论是普通枚举还是强制枚举，每个枚举常量底层都对应一个整数值（默认从 0 开始递增，也可以手动指定）。 但在实际编程中，我们真正关心的是枚举常量本身的意义，而不是它底层是 0 还是 1 还是 2

问题：

所有枚举常量暴露在同一个作用域（全局或命名空间）中，不同枚举列表的常量名不能重复。

没有类型隔离，不同语义的枚举混在一起非常难受。

2. #define 的缺点

问题：

不集中：每个常量单独一行，难以管理。

没有类型：就是简单的文本替换，调试不友好。

全局污染：同样无法解决命名冲突。

多组状态机共用整数空间：比如第一组用了 0、1、2，第二组如果也想用 0、1、2，要么冲突，要么手动错开编号，非常繁琐。

enum class（强制枚举）的解决方案

声明与使用

使用方式：

为什么可以重复常量名？ 因为访问时必须加上 枚举类名::，编译器能区分 Color::RED 和 Status::RED，底层整数即使相同也没关系，类型不同。

底层整数值

默认情况下，enum class 的第一个常量底层也是 0，依次递增。 但你通常不需要关心具体数值，因为不能像 C 风格那样隐式转成整数

与 #define 或普通 enum 写状态机的区别

用宏定义实现状态机

1. 集中管理

#define：每个常量单独一行，分散、无关联。

enum class：一组相关的常量写在一个地方，逻辑上成块。

2. 多组状态机共用底层整数空间

使用 #define 或普通 enum 时：

第一组状态机用了 0,1,2

第二组如果想重用 0,1,2 就会冲突（要么重复定义，要么覆盖）

解决办法是手动错开编号（比如第二组从 10 开始），但这很麻烦且容易出错

使用 enum class 时：每个枚举类独立的作用域（类名隔离）

不同枚举类的底层整数可以完全一样（比如都从 0 开始），不会互相干扰

因为你访问时带上了 枚举类名::，编译器知道它们是不同的类型，即便整数相同也不冲突

switch-case：实现状态机的分支语法

switch 语法

表达式 必须是整数类型（int、char、enum 等）

case 后面跟的是常量，不能是变量

break 用来跳出 switch，不写会继续往下执行（“穿透”）

default 是可选的，处理其他情况

switch 更适合写状态机

**一个状态对应一个 **case 状态机的每个状态恰好对应 switch 里的一个 case，代码结构和状态图一一对应，清晰直观。

状态切换集中在一处 所有状态的切换逻辑都在同一个 switch 结构里，不用到处找 if-else 嵌套

代码更干净 没有一堆 else if (current == 枚举类名::XXX) 的重复、冗长的判断条件，case 枚举类名::XXX: 更短更整齐

用 switch + enum class 写状态机

#include

using namespace std;

// 1. 定义状态（强制枚举）

enum class State {

IDLE,

RUNNING,

STOPPED

};

int main() {

State current = State::IDLE; // 当前状态

int progress = 0;

// 模拟状态机循环

for (int i = 0; i < 10; i++) {

switch (current) {

case State::IDLE:

cout << “空闲状态，切换到运行” << endl;

current = State::RUNNING;

break;

case State::RUNNING:

cout << “运行状态，进度 +1” << endl;

progress++;

if (progress >= 3) {

cout << “进度满了，切换到停止” << endl;

current = State::STOPPED;

}

break;

case State::STOPPED:

cout << “停止状态，结束循环” << endl;

return 0; // 结束程序

}

}

return 0;

}

内部类与外嵌类

在一个类（称为外嵌类）的内部再定义另一个类，这个被定义的类称为内部类。

注意：内部类与类的成员对象是不同的。类的成员对象指的是：在本类的外部，已有某个类的完整声明，然后在本类中直接使用这个类的类名来创建一个对象，作为本类的成员。

内部类的双重层级：

本文后续按照外嵌类的视角来叙述，因此我们说：内部类（对外嵌类而言）是对象级的

内部类的使用方式：

内部类创建的对象，被当作外嵌类的成员对象来使用，和普通成员变量类似——内部类的类名就当作成员变量的类型。

也就是说，当一个外嵌类创建了一个对象后，我们可以通过以下方式访问对象当中的内部类对象：

由于内部类对象本身也是一个对象，可以继续用 . 访问它自己的成员：

这样，一个外嵌类对象中可以拥有多个相同类型的内部类对象（如 对象.inner1.a 和 对象.inner2.a），各自独立存储、互不干扰，实现更灵活的数据组织结构,这就是内部类的用途之一。

#include

using namespace std;

class 外嵌类 {

public:

class 内部类 {

public:

int a = 0; // 内部类的成员变量

};

内部类 inner1;//内部类对象1 作为外嵌类的成员变量

内部类 inner2;//内部类对象2 作为外嵌类的成员变量

};

int main() {

外嵌类 obj;

// 各自独立存储，互不干扰

obj.inner1.a = 100;

obj.inner2.a = 200;

cout << obj.inner1.a << endl; // 输出 100

cout << obj.inner2.a << endl; // 输出 200

}

静态内部类的层级升级

在内部类前加上 static 关键字，这个内部类就会从对象级升级为类级

#include

using namespace std;

class 外嵌类 {

public:

// 普通内部类（对象级）

class 普通内部类 {

public:

int a = 10;

};

// 静态内部类（类级）

static class 静态内部类 {

public:

int a = 20;

};

// 用普通内部类声明成员对象（这样才能在外部通过外嵌类对象访问）

普通内部类 inner;

};

class 其他普通类 {

public:

外嵌类::静态内部类 obj2;

//其他普通类中可以直接通过外嵌类的类名访问静态内部类，并创建对象

//普通类当中都可以建立别的类的对象，这说明把静态内部类当作一个普通类来使用了

};

int main() {

外嵌类::静态内部类 x;// 直接通过外嵌类类名接::静态内部类类名 然后创建对象

//因为静态内部类是类级的，所以可以直接通过外嵌类的类名访问并创建对象

x.a = 100;

cout << x.a << endl;

外嵌类 outer;//必须先创建外嵌类对象，再访问其成员对象

outer.inner.a = 999;

cout << outer.inner.a << endl;

}

子类构造函数转发

我们平常展示子类父类关系时，会先构造一个父类对象、再构造一个子类对象，用来分别演示各自的调用。但不要误以为：必须先创建一个父类对象，才能创建一个子类对象。

实际上，这个独立的父类对象和子类对象没有任何关系——它们是两个独立的内存实体。

子类对象在创建时，会自动调用父类的构造函数（默认是默认构造），将父类的内容作为子类对象的一部分构建进来。这一切都发生在子类对象创建的过程中，与外部的任何父类对象无关。

也就是说：

外部先创建一个父类对象（无论用什么方式构造，或之后如何修改），都不会影响下一行创建的子类对象内部所包含的父类内容。

直接创建子类对象时，默认会调用父类的默认构造。

那么问题来了：如果我们希望在创建子类对象的同时，也能一并指定子类对象内部那个「父类部分」的初始值，该怎么做？

答案就是：子类构造函数转发（通过初始化列表显式调用父类的含参构造函数）。

普通枚举和强制枚举类型

1. 传统 C 枚举 / 普通 enum 的痛点

传统写法：

普通枚举的声明格式是：enum 枚举名 { 常量1, 常量2, ... };

例如：

无论是普通枚举还是强制枚举，每个枚举常量底层都对应一个整数值（默认从 0 开始递增，也可以手动指定）。但在实际编程中，我们真正关心的是枚举常量本身的意义，而不是它底层是 0 还是 1 还是 2。

问题：

  • 所有枚举常量暴露在同一个作用域（全局或命名空间）中，不同枚举列表的常量名不能重复；
  • 没有类型隔离，不同语义的枚举混在一起非常难受。

2. #define 的缺点

问题：

  • 不集中：每个常量单独一行，难以管理；
  • 没有类型：就是简单的文本替换，调试不友好；
  • 全局污染：同样无法解决命名冲突；
  • 多组状态机共用整数空间：比如第一组用了 0、1、2，第二组如果也想用 0、1、2，要么冲突，要么手动错开编号，非常繁琐。

1. 集中管理

  • #define：每个常量单独一行，分散、无关联；
  • enum class：一组相关的常量写在一个地方，逻辑上成块。

2. 多组状态机共用底层整数空间

使用 #define 或普通 enum 时：第一组状态机用了 0、1、2，第二组如果想重用 0、1、2 就会冲突（要么重复定义，要么覆盖）。解决办法是手动错开编号（比如第二组从 10 开始），但这很麻烦且容易出错。

使用 enum class 时：每个枚举类有独立的作用域（类名隔离），不同枚举类的底层整数可以完全一样（比如都从 0 开始），不会互相干扰。因为你访问时带上了 枚举类名::，编译器知道它们是不同的类型，即便整数相同也不冲突。

switch-case：实现状态机的分支语法

switch 语法

  • 表达式必须是整数类型（int、char、enum 等）；
  • case 后面跟的是常量，不能是变量；
  • break 用来跳出 switch，不写会继续往下执行（「穿透」）；
  • default 是可选的，处理其他情况。

switch 更适合写状态机

  • 一个状态对应一个 case：状态机的每个状态恰好对应 switch 里的一个 case，代码结构和状态图一一对应，清晰直观；
  • 状态切换集中在一处：所有状态的切换逻辑都在同一个 switch 结构里，不用到处找 if-else 嵌套；
  • 代码更干净：没有一堆 else if (current == 枚举类名::XXX) 的重复、冗长的判断条件，case 枚举类名::XXX: 更短更整齐。

内部类与外嵌类

在一个类（称为外嵌类）的内部再定义另一个类，这个被定义的类称为内部类。

注意：内部类与类的成员对象是不同的。类的成员对象指的是：在本类的外部，已有某个类的完整声明，然后在本类中直接使用这个类的类名来创建一个对象，作为本类的成员。

内部类的双重层级：

本文后续按照外嵌类的视角来叙述，因此我们说：内部类（对外嵌类而言）是对象级的。

内部类的使用方式：

内部类创建的对象，被当作外嵌类的成员对象来使用，和普通成员变量类似——内部类的类名就当作成员变量的类型。

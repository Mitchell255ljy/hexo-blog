类、实例/对象、成员与方法

先厘清几个面向对象中最基础的概念：

  • 类（Class）：类就是自定义的类型。
  • 实例/对象（object）：根据类型声明的变量，就是类的对象（实例）。
  • 成员（Member）：对象里包含的成员变量和成员函数，统称成员。
  • 方法（Method）：特指成员里的函数。

由于外部传入的参数和成员变量容易混淆，业界有一种习惯：给成员变量命名时在前面加上前缀 m_（m 是 member 的缩写），例如 m_id、m_name，用来和形参做区分。

析构函数

可理解为「销毁函数」：在变量销毁时自动调用的函数，负责清理资源。

变量何时销毁？

堆内存上声明变量

new 关键字会在堆区建立一个内容，然后返回它的地址值。

因为堆区内存「一直占用、不主动释放」的特性

这会导致有时堆区上的变量会遇见在栈区上见不到的错误：内存泄漏与重复释放。

内存泄漏

内存泄漏的根本原因

用 new 绑定堆内存后，堆内存会一直被占用，不会主动释放。

内存泄漏：程序在堆上分配了内存，但无法释放，导致这块内存既不属于程序可用内存，也不被操作系统回收，造成内存浪费。常见的两种情况：

  1. 忘记用 delete 关键字释放；
  2. 还没来得及 delete，指针就被赋了新地址，导致程序失去了对原地址的控制（想释放也没法释放了）。

浅拷贝、深拷贝、值拷贝与成员逐个拷贝

一个前提

指针成员通常用关键字 new 取堆区地址，来指向堆区上的内容；销毁时则会写配套的析构函数，在里面用 delete 释放指针指向的堆区内存。

下面讨论的都是「指针成员指向堆区内存」的情况。

成员逐个拷贝

「成员逐个拷贝」形容的是默认拷贝构造函数的系统行为：

  1. 对基本类型（int、string、double 等）逐个拷贝，这叫值拷贝；
  2. 对类类型，调用它自己的拷贝构造函数；
  3. 对指针，也是执行值拷贝——指针的内容就是地址，它的「值拷贝」就是拷走地址。于是拷贝项和原项共用一个地址指向的内容，这叫浅拷贝（浅拷贝就是指针值拷贝的特殊说法）。

浅拷贝（Shallow Copy）

浅拷贝创建的对象并不拥有独立的数据副本，而是与原对象共享同一块内存地址中的数据——因为浅拷贝只复制了堆上的指针值，并没有复制堆里的实际数据。

深拷贝（Deep Copy）

由于包含指针成员的对象在生命周期结束时，会调用 delete 释放其指向的内存；如果有一个指针对象浅拷贝了另一个先被 delete 的指针对象（两个指针处于不同地址、但指向同一地址），那么当它再 delete 时，就会重复释放一块已经释放掉的堆内存，引发双重释放，程序报错。

因此，如果你需要让两个指针变量指向两块独立的堆内存（这样就能各自释放各自的内存），就必须使用深拷贝（Deep Copy）——完整地复制堆中的实际数据，放到两块独立堆内存上，而不是仅复制对方指针的值（指针的值就是指向的地址）、导致两个指针变量指向同一块堆内存。

关键字 new 的作用理解

new 类型 是在堆上分配内存并新建一个该类型的对象，并返回该对象的地址。

类名:: 实现函数的外部定义

类名::成员 是对「需内部声明、外部定义」的成员，在外界时强调它的归属关系。这里涉及构造函数、析构函数、成员函数等。

后面还有一种用 static 关键字使成员变量变为「强制内部声明、外部定义」的变量，这里先不提及。

类的成员对象（或叫对象成员）

注意：不宜称为「类成员」或「成员类」

这两个术语容易和「内部类」混淆。「成员类」通常指的是在一个类内部声明的完整类（即内部类）；而「类的成员对象」指的是：把本类外部的另一个已声明的类，在本类中创建一个该类的对象作为成员——这个对象的类型是在本类之外定义的，而不是在本类内部定义的。

类的对象成员的特殊性：有自己独立的生命周期

类的对象成员就是一个独立的对象，它和普通对象没有任何区别。对象成员的生命周期完全在宿主类中，在类的范围内走完构造、析构等过程。

准确来说：在宿主类构造前构造，在宿主类析构后析构。

父对象与子对象

在这里，「父对象/子对象」不是指「父类的对象」和「子类的对象」，与后续章节要讲的「父类/子类」中的「父/子」含义不同：

本文只讨论父对象与子对象，不涉及继承。

父对象与子对象的定义

前提条件：在一个类的定义中，把另一个类声明的对象作为该类的成员变量。

产生的结果：当含有成员对象的类被用来创建对象时，就会形成一个「对象中包含另一个对象」的结构。

命名规则：

  • 外部的、包含其他对象的对象，称为父对象；
  • 内部的、被包含在父对象中的对象，称为子对象。

四个要点：

  1. 包含关系：父对象持有子对象，子对象从属于父对象。
  2. 创建顺序：父对象创建时，其内部的子对象也随之创建。
  3. 访问方式：通过 父对象.子对象 的链式写法，可以访问子对象及其方法。
  4. 生命周期：通常情况下，父对象销毁时，其内部的子对象也随之销毁。

前向声明的类作成员

指针和引用都需要指向「真实存在的对象」。

指针开始时不存在真正对象，建立了 new 内存后才能是真的对象——new 是手段不是目的，不是为了让 ren 成为一个堆上的指针，而是用 new 返回地址的作用，实现指向一个具体的对象。

刚开始光引用没对象，用了构造函数的初始化列表立刻传值，让这个引用有了具体对象。

类名成员函数（为了返回对象）

类名成员函数主要分两类

  1. 普通类名成员函数 类名 函数名() {}
    • 一般在内部声明临时对象，返回临时对象的值。
  2. 引用类名成员函数 类名 &函数名() {}
    • 一般用 *this 来返回自身对象的值。

注意和普通成员函数、构造函数区分

  • 类名() {}：类名和形参列表之间无函数名，即为构造函数。
  • void func() {}：无返回值类型，是普通的成员函数。

值得注意的是

  • 引用类名函数：引用的是原对象；
  • 非引用类名函数：得到的是原对象的副本，是值传递；
  • 想要修改成员值，就调用引用类名函数。

全局类名函数（为了返回对象）

当在类的外部以 类名 函数名() {} 的形式声明时，就是全局类名函数。

那么如何区分「外部封装的类名函数」「类名成员函数」「全局类名函数」呢？

1. 类名成员函数的外部封装

类内：类名 函数名();

2. 类名成员函数

仅类内：类名 函数名() {}

3. 类名全局函数

仅类外：类名 函数名() {}

三者的关系是：类名成员函数和外部封装的类名成员函数，都是成员函数，用 . 调用；而全局类名函数是全局函数，需要用 类名 函数名(); 的方式调用。

静态变量与静态方法

静态成员的声明方法就是前接 static

静态成员即为一个类的所有对象共享的成员，相当于「自动的浅拷贝」。

  • 静态变量：类内声明，类外定义并赋值（如果在类内赋值，就和成员变量特征一样了，故类内仅声明）；
  • 静态方法：全在类内完成。

如何理解「静态成员除了用 . 访问，还可以通过 类名:: 访问」？

因为普通成员不是共享的，具体值受对象层次局限；而静态成员的层次在类级，所以静态成员可以通过 类名:: 访问，普通成员却不能——类名:: 是一种类级层次的访问手段，对普通成员来说过于「模糊」。

this 指针

this 指针就是指向被调用函数所属对象的地址

this == MyClass* 当前对象，this 等价于 MyClass 类的当前对象的地址。

  • this->成员a：为 MyClass* 当前对象的解引用再访问其成员 a；
  • return *this：返回 MyClass* 当前对象地址的解引用，即返回对象本身。

事实上，在成员变量访问时，编译器会自动补全 this->——成员变量操作时，前面都暗含了一个 this-> 解引用再访问的过程。

你有没有想过：this 指针存在的原因是什么？为什么要用 this-> 来解出成员变量的值？

this 指针常量、常函数、常对象

this 是一个指针常量

this 指针本质是一个指针常量，和普通的指针不同，它不能被修改自身内容（即指向的地址）。

常函数的形式与规则

成员函数后接 const（void func() const {} 的形式），就能让 this 指针指向的具体值也不能修改。准确地说，常函数限制的是「受 this 调用（即成员变量）」值的修改，非成员变量依旧不受限。

但如果声明成员变量时前接关键字 mutable（译为「可变的」），就能打破常函数的规则。

常对象就是更严苛的不可修改的对象

为了保证自身属性不变，常对象只能调用常函数，但依旧会被 mutable 打破。

构造与析构函数

从名字就能看出它们的用途：

构造函数：在变量创建时自动调用的函数，负责初始化

析构函数（可理解为”销毁函数”）：在变量销毁时自动调用的函数，负责清理资源

变量何时销毁？

当程序执行离开变量所在的作用域时，变量就会自动销毁。具体来说，就是遇到它所属的那层大括号 } 的一瞬间。

简单说：构造函数 = 出生时的啼哭，析构函数 = 离世时的告别

堆内存上声明变量

new关键字会建立一个内容在堆区 然后返回其地址值

因为堆区内存的一直占用不主动释放的特性

这就会导致有时堆区上的变量会遇见在栈区上见不到的错误 内存泄露 与 重复释放

内存泄漏

内存泄漏的根本原因:

用new绑定堆内存后,堆内存会一直被占用,不会主动释放

内存泄漏：程序在堆上分配了内存，但无法释放（1忘记使用delete关键字释放，2没delete呢就被赋值了新地址 导致对原地址失去了对它的控制），导致这块内存既不属于程序可用内存，也不被操作系统回收，造成内存浪费。

浅拷贝、深拷贝、值拷贝与成员逐个拷贝

我们需要知道一个前提：

指针成员通常用关键字new取堆区地址来指向堆区上的内容,销毁则会写配套的析构函数,里面会用关键字delete释放指针指向的堆区内存

下面讨论的都是指针成员指向堆区内存上的情况

成员的逐个拷贝是形容默认拷贝构造函数的系统行为

它会遍历类的每个成员进行拷贝，

1对基本类型执行(int string double等)叫做值拷贝

2对类类型调用其拷贝构造函数

3对指针也是执行值拷贝（指针的内容就是地址 它的值拷贝就是拷走地址 这样拷贝项与原项共用一个地址指向的内容 这样也叫浅拷贝，浅拷贝是指针的值拷贝的特殊说法），而深拷贝则需要程序员手动实现。

浅拷贝（Shallow Copy）创建的对象并不拥有独立的数据副本，而是与原对象共享同一块内存地址中的数据。这是因为浅拷贝仅复制了堆上的指针值，并未复制堆中的实际数据。

由于包含指针成员的对象在生命周期结束需要后调用delete释放指向的内存，而且有一个指针对象浅拷贝了先delete的指针对象(两指针处于不同地址但指向地址相同的状态),这就会导致它再delete的时候会重复释放一个已经空掉的堆内存 引发双重释放 程序报错

因此，如果你需要使得两个指针变量指向两个堆内存(这样可以各个释放各个的内存)，就必须使用深拷贝（Deep Copy）——丛诳奖词蓖暾粗贫阎械氖莶�放到两个独立堆内存上，而不是仅复制引用对方的值(指针的值为指向地址)导致两个指针变量指向一个堆内存。

关键字new的作用理解

new 类型 是在堆上分配内存并新建一个该类型的对象 并返回该对象的地址

#include

using namespace std;

class MyClass {

public:

int* data;//指针成员 才开始分浅拷贝(值拷贝)和深拷贝

// 构造

MyClass(int x) {//指针变量一般在堆区上建立 所以我们写了一个堆区构造函数

data = new int(x); //new 在堆上新建int x1 并返回其地址,让a.data内容等于了堆上x1的地址 也就是对象a的成员指针data指向了堆内存上的x1 成为了堆指针

}

// 深拷贝

MyClass(const MyClass& other) {//other 传进来是个类

data = new int(other.data);//注意这是other.data 不是(*other).data 也就是说这是先访问other的成员data 然后再解引用 不是把a这个对象解开再访问 别理解错了

//用new int在堆上新建了一个int x2 对象,值等于 *other.data 的值(先访问成员再解引用)也就是堆上的x2等于了堆上x1的值 并返回了x2的地址

//使得对象b的成员指针data 和a的成员指针都指向了堆 且地址不相同 但是指向的值都为5

}

// 析构

~MyClass() {

delete data;//data指向的堆内存需要自己释放 这样data指向的内存就被屏蔽了

data = NULL;//然后再清空data指针自身的内容再清空 防止再调用释放过的堆内存

}

};

int main() {

MyClass a(5);//对象a 构造函数new int 申请了堆内存

MyClass b = a; //对象b 深拷贝函数的new int申请了堆内存并得到其值

//赋值初始化形式 MyClass b=a也是拷贝构造

*a.data = 10; // 改a

cout << *a.data << endl; // 解引用a并访问其成员data 输出为10

cout << *b.data << endl; // 5 (独立)

return 0;

}

类的成员对象（或叫对象成员）

注意：不宜称为“类成员”或“成员类”，因为这两个术语容易与“内部类”混淆造成理解错误。“成员类”通常指的是在一个类内部声明的完整类（即内部类）。而“类的成员对象”指的是：将本类外部的另一个已声明的类，在本类中创建一个该类的对象作为成员。也就是说，这个对象的类型是在本类之外定义的，而不是在本类内部定义的//类的对象成员的特殊性:

有自己独立的生命周期

类的对象成员就是一个独立的对象,它和普通对象没有任何区别

对象成员的生命周期完全在宿主类中 在类的范围内走完构造析构等等过程

生命周期准确来说是 在宿主类构造前构造 在宿主类析构后析构

父对象与子对象

在这里 父对象/子对象 不是指父类的对象和子类的对象，与后续章节要讲的 父类/子类 中的“父/子”含义不同：

本文只讨论父对象与子对象，不涉及继承。

父对象与子对象的定义

前提条件：

在一个类的定义中，将另一个类所声明的对象作为该类的成员变量。

产生的结果：

当含有成员对象的类被用来创建对象时，就会形成一个“对象中包含另一个对象”的结构。

命名规则：

外部的、包含其他对象的对象，称为 父对象

内部的、被包含在父对象中的对象，称为 子对象

1包含关系：父对象持有子对象，子对象从属于父对象。

2创建顺序：父对象创建时，其内部的子对象也随之创建。

3访问方式：通过 父对象.子对象 的链式写法，可以访问子对象及其方法。

4生命周期：通常情况下，父对象销毁时，其内部的子对象也随之销毁。

类名成员函数(为了返回对象)

类名成员函数主要分两类

一类是普通类名成员函数 类名 函数名(){}

一般内部声明临时对象 返回临时对象的值

一类是引用类名成员函数 类名 &函数名(){}

一般*this 来返回自身对象的值

注意和普通成员函数构造函数区分

类名(){} 类名和形参列表间无函数名 即为构造函数

void func(){} 无返回值类型的 普通的成员函数

#include<bits/stdc++.h>

using namespace std;

class MyClass {

public:

int 成员=-1;

int func() {//普通类型的成员函数

int b=100;

return b;

}

MyClass() {//构造函数

cout << “有人调用了构造！\n”;

}

~MyClass() {

cout << “某个对象析构了\n”;

}

MyClass func3() {//类名 成员函数

//需创建临时对象 就像func()一样 为了返回一个int类型 我们创建了临时变量int a 在这里我们创建临时对象temp

MyClass temp;//临时对象temp 在这里被构造

temp.成员 = 3;

return temp;//func3()返回临时对象的值

}//在这里临时对象temp被析构 生命周期结束

MyClass &func4() {//引用类 成员函数

成员 = 2;//这里修改的对象a的成员值

return *this;//返回对象a

}

};

int main() {

MyClass a;

cout<<”返回”<<a.func() << endl;

cout << “类函数返回对象的成员值为”<<a.func3().成员<<endl;//返回的是temp的成员值3

cout << “对象a的成员值为” << a.成员 << endl;//a的成员值经过func3()没变

cout << “引用类函数返回对象的成员值为”<<a.func4().成员<<endl;

}

值得注意的是

引用类名函数 引用的原对象

非引用类名函数 得到的是原对象的副本 是值传递

想要修改成员值就调引用类名函数

全局类名函数(为了返回对象)

当在类的外部声明 类名 函数名(){}的形式时就是全局类名函数

但是如何区分

外部封装的类名函数 类名成员函数 全局类名函数呢

1类名成员函数的外部封装

类内 类名 函数名();

类外 类名::类名 函数名(){}//表明外部封装的类名::和返回类型是类名 连在一起别搞混

2类名成员函数

仅类内 类名 函数名(){}

3类名全局函数

仅类外 类名 函数名(){}

三者的关系是 类名成员函数 和 外部封装的类名成员函数 都是成员函数 用 .调用

而全局类名函数 是全局函数 需要用 类名 函数名();的方式调用

静态变量与静态方法

静态成员的声明方法就是前接static

静态成员即为一个类的所有对象的共享成员 相当于自动的浅拷贝

静态变量类内声明 类外定义成员并赋值(如果是在类赋值 就和成员变量特征一样了 故类内仅声明) 静态方法全在类内完成

如何理解静态成员除了.来访问 还可以通过类名::访问？

因为普通成员不是共享的，具体值受对象层次局限，但是静态成员的层次在类级 故静态成员可以通过 类名::访问 但是普通成员却不能用类名::这种类级层次的模糊访问手段

#include<bits/stdc++.h>

using namespace std;

class MyClass{

public:

static int a;//类内声明是静态

int b;

static void func(int c) {//静态成员函数 内部只能访问静态成员变量 和自身的局部变量(包括形参变量) 因为这个函数是共享的 里面涉及非共享值 它不知道用哪个对象的值作为基准 故只能调用共享变量

cout << “参数为”<<c<<”静态func函数调用了局部变量！\n”;

cout << “参数为”<<a<<”静态func函数调用了静态成员变量！\n”;

//b = 200;//b不是静态变量 取消注释就会报错

}

};

int MyClass::a =0;//类外定义成员并赋值是为了方便全体对象直接改共享值

int main() {

MyClass a,b;

cout << a.a <<” “<<b.a <<endl;

MyClass::a = 200;//除了用点访问成员a之外,也可以通过MyClass的命名空间 直接访问成员a 你可能对于这种写法难以理解

我告诉你啊 这个和上面提及的封装外部函数一样 类名::成员 就是仅在内部声明 外部定义的成员调用方式 静态变量这种方式在外部定义 也就是说 静态变量可以 但是普通变量不行

cout << a.a<<” “<<b.a<<endl;

a.a = 300;//通过对象的成员 可以实现类外赋值

cout << a.a << “ “ << b.a << endl;

a.func(1);//静态成员函数可以通过对象访问

MyClass::func(2);//静态成员函数可以通过命名空间访问

}

this指针

this指针就是指向被调用函数的所属对象地址

this==MyClass*当前对象 this等价于MyClass类的当前对象的地址

故有this->成员a 为MyClass*当前对象的解引用再访问其成员a

return this 为返回MyClass当前对象地址的解引用 即返回对象本身

#include<bits/stdc++.h>

using namespace std;

class MyClass {

public:

int a=50;

void func(int a) {

//第一个作用 解决名称冲突

//a+=a; //混淆了

this->a += a;//左边的a是成员,右边的a是形参 如果不加this->强调左边a是当前对象的成员 那么编译器会混淆形参a和成员a

cout << this->a<<endl;

}

MyClass &ADD(int a) {//加&来实现返回MyClass的引用 即对象本身 否则传进来就是值拷贝的副本了

this->a += a;//这个this是为了指明a是成员变量

return this;//这个this 是引用类 函数返回值(需要是个类)的必须,这样返回解引用this就返回了当前对象

}

};

int main() {

MyClass a,b;

a.func(100);

cout << b.ADD(100).ADD(50).ADD(10).a;//实现了链式调用

}

事实上 在成员变量访问时 编译器会自动不全this->

成员变量操作时前面都暗含了一个this->解引用再访问的过程

你有没有想过 this指针的存在原因是什么 为啥要用一个this->来实现解出成员变量的值

空指针与->和(* ).

#include<bits/stdc++.h>

using namespace std;

class MyClass {

public:

int m_a=50;

void show1(int a) {

if (this == NULL)return; //注释这行马上就崩 因为m_a 前面暗含了this-> 这就会把空指针解开 显然这是不可能的

cout << (m_a += a);

}

void show2() {//不涉及this-> 不崩

cout << “芜湖\n”;

}

void show3(int a) {//不涉及this-> 不崩

cout << a << endl;

}

};

int main() {

MyClass* p = NULL;

p->show1(1);

p->show2();//-> 包容性比(*). 高 因为它调用函数不解引用 所以可以一个空指针居然能过show2 show3

//但是到了成员变量暗含(this->)要强制解开再引用的时候 空指针导致解不开就崩溃了 就是show1()

p->show3(3);

(*p).show2();//一般来说 这个就是强制先解引用后访问 大部分编译器会在解引用的时候就崩了 但是我的编译器给做了优化 跳过了解引用步骤导致没崩

}

this指针常量 常函数 常对象

this是一个指针常量

this指针本质是一个指针常量 和普通的指针不同 它不能被修改自身内容即指向地址

常函数的形式与规则

成员函数后接const (void func()const{}的形式) 就能让this指针指向的具体值也不能修改 准确的说 常函数限制(受this调用即)成员变量值的修改 但是非成员变量依旧不受限

但是如果在声明成员变量的时候 前接固有字mutable(译为 可变的) 就能打破常含数规则

常对象就是更严苛的不可修改的对象

为了保证自身属性不变 只能调用常函数 但是依旧会被mutable 打破

#include<bits/stdc++.h>

using namespace std;

int qwe=0;

class MyClass {

public:

int a=-1;

mutable int b=-1;//metable 可变的 这个前缀强制成员变量b的值可变 不受常函数规则限制

void func() {

//this = this;//取消注释就报错左端是指针常量不能修改内容 哪怕是等于自己

a = 10;//但是this->a 是可以修改a的值的

}

void func2()const {

//a = 20; //取消注释就报错 常函数不允许成员变量的值被修改 因为this指针指向的地址对应的内容被封锁了

b = 30;

qwe = 123;//全局变量不受this指针来调用 常函数不能限制它

}

};

int main() {

int m, n;

int* p = &m; p = &n;//普通指针可以修改指向地址对应的内容 合法 不报错

MyClass obj;

obj.func();

obj.func2();

cout << obj.a << “ “ << obj.b << “ “ << qwe << endl;

qwe = 0;

const MyClass obj2;//常对象 常对象任何成员不允许修改 为了防止常对象的成员被非常函数(func())修改 故常对象只能调用常函数

//obj2.func() //取消注释就报错

obj2.func2();

cout << obj2.a << “ “ << obj2.b << “ “ << qwe << endl;

}

friend关键字前缀 在类内声明这是友元

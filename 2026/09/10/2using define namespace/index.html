作用域空间

写程序时我们经常遇到一个麻烦：变量名不够用。如果所有变量都挤在同一个大空间里，起名字就得小心翼翼，生怕重名互相覆盖、互相干扰。解决这个麻烦的第一件工具，就是作用域。

很多人以为 { } 必须跟 if、while、函数之类的关键字一起使用，其实不是。{ } 可以独立存在，它就是一块「作用域空间」。

作用域空间利用「退出即销毁」的特性，用来限制变量的生命周期，避免资源占用和命名冲突。

也就是说，作用域是一块临时的隔离空间：进去的时候东西才「出生」，一退出就「死亡」。它能在局部帮你挡掉命名冲突，但有个局限——它太「短命」了，出了这个 { } 就作废。如果想让隔离跨文件、长期有效，就需要下面要讲的命名空间。

命名空间和 namespace 关键字

命名空间的内容永久存在、跨文件可见、需要用前缀访问。

std 是 C++ 标准库中的命名空间，封装了大部分的标准库实现。C++ 标准库中的大多数名称（如 cout、vector、sort）都定义在 std 命名空间中，默认情况下使用它们时需要加上 std:: 前缀。

更换命名空间调用前缀

可以用 namespace 关键字给命名空间起一个更短的前缀：

using

有了命名空间，隔离是安全了，但每次访问都要写一长串前缀（比如 std::），写起来很累。using 关键字就是用来「省前缀」的，它有两种用法：给类型起别名、做命名空间操作。

给类型起别名

using 可以给类型起别名，但它有很大的局限性——只能对类型进行操作，不能像 using a = 2 这样定义值。

关于 using namespace std; 的作用

C++ 标准库的所有内容（如 cout、string 等）都被封装在 std 命名空间中。如果不使用这条指令，就需要写成 std::cout 这样的形式；而通过 using namespace std; 可以简化代码，减少重复输入 std:: 的冗余。

C++ 标准库里的 <algorithm>（包含 max() 等）、<vector>（常用的 vector 容器）、<iostream>（包含 cout、cin 等基本输出方式）等头文件，都是我们常用的。如果不用 using namespace std;，那么每个头文件里的函数、容器都要在前面接 std:: 再使用。

宏命令 #define

回顾上一篇：#define 是预处理指令大家族里的一员。using 能简化类型和命名空间，但有些事它做不到，这时就得请出「简单暴力」的 #define 了。

宏命令就是预处理指令的一种。define 的英文词义就是「定义」。

最简单的应用是「空定义」：#define a（定义了一个空的内容），实现空定义变量 a。

定义变量和值

从上至类型替换、下到变量替换都能实现，体现了「文本替换」的特性。这一点是 using 做不到的——using 只能操作类型，而 #define 就是简单暴力的文本替换，可以把 PI 替换成 3.14159，实现值的定义。

这里要提醒一句：正因为 #define 是「纯文本替换」，它不检查类型、也不会先求值，所以很容易踩坑。比如 #define sq(x) x*x 在 sq(2+3) 时会被替换成 2+3*2+3，结果就不是你想要的 25 了。所以宏里习惯给每个参数和整体都套上括号：#define sq(x) ((x)*(x))。
